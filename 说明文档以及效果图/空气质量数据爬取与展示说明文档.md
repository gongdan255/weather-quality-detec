# 城市空气质量数据爬取与可视化系统说明文档

## 一、项目概述

本项目实现全国城市空气质量数据的自动化爬取、入库存储与前端可视化展示。后端基于 Spring Boot 定时从中国环境监测总站公开接口采集数据，经校验后存入 MySQL；前端基于 Vue + ECharts 构建可视化驾驶舱，以地图散点、排行榜、区域对比图表等多种形式实时呈现全国空气质量态势。

数据来源：中国环境监测总站空气质量实时发布接口

```
https://air.cnemc.cn:18007/CityData/GetAQIDataPublishLive?cityName={城市名}
```

系统按城市候选列表逐个并发请求接口，仅保存接口真实返回数据的城市，不伪造任何数据。

## 四、数据库设计

### 建库脚本

库名 `weather_analysis`，字符集 `utf8mb4`。建表脚本位于 `backend/src/main/resources/db/schema.sql`。

### 表结构 `air_quality_record`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | 主键，自增 | 主键 |
| province | VARCHAR(32) | NOT NULL | 省份 |
| region | VARCHAR(16) | NOT NULL | 区域（华北/华东/华南/华中/西南/西北/东北） |
| city | VARCHAR(32) | NOT NULL | 城市名（站点记录为“城市-站点名”） |
| aqi | INT | NOT NULL | AQI 指数 |
| pm25 | DECIMAL(8,2) | 可空 | PM2.5 |
| pm10 | DECIMAL(8,2) | 可空 | PM10 |
| co | DECIMAL(8,2) | 可空 | 一氧化碳 |
| no2 | DECIMAL(8,2) | 可空 | 二氧化氮 |
| quality_level | VARCHAR(16) | NOT NULL | 空气质量等级 |
| temperature | DECIMAL(5,2) | 可空 | 温度（接口未返回时为 NULL） |
| humidity | DECIMAL(5,2) | 可空 | 湿度（接口未返回时为 NULL） |
| monitor_time | DATETIME | NOT NULL | 监测时间 |
| created_at | DATETIME | NOT NULL，默认当前时间 | 入库时间 |

### 索引与约束

```sql
INDEX idx_city_time (city, monitor_time)      -- 城市与时间查询
INDEX idx_region_time (region, monitor_time)  -- 区域与时间查询
INDEX idx_aqi (aqi)                            -- AQI 排序
UNIQUE KEY uk_city_time (city, monitor_time)  -- 防止同一城市同一时间重复入库
```

唯一约束 `uk_city_time` 保证同一城市同一监测时间不会重复入库；入库时若触发冲突，会捕获 `DuplicateKeyException` 静默跳过，不影响其他记录入库。

## 五、爬虫模块

### 5.1 城市候选列表

候选城市配置文件：`backend/src/main/resources/data/city-candidates.csv`，共 725 个候选城市。

CSV 文件格式（4 列，代码实际使用前 3 列）：

```

北京,北京市,北京,北京市
石家庄,石家庄市,河北,石家庄市
```

| 列 | 字段 | 用途 |
|----|------|------|
| 第 1 列 | city | 入库城市名、显示用 |
| 第 2 列 | api_city | 接口请求时拼装的城市名 |
| 第 3 列 | province | 省份归属，用于区域归类 |
| 第 4 列 | source_name | 数据源备注（代码未使用） |

### 5.2 名称映射

接口对部分自治州/地区的命名与行政简称不一致，代码内置 30 个名称映射（`AirQualityCrawler.API_CITY_NAME_OVERRIDES`），例如：

```
恩施     → 恩施土家族苗族自治州
湘西     → 湘西土家族苗族自治州
大兴安岭 → 大兴安岭地区
伊犁     → 伊犁哈萨克自治州
延边     → 延边朝鲜族自治州
```

若 `API_CITY_NAME_OVERRIDES` 中存在映射，则优先使用映射名；否则按 `api_city` 列的值请求；若仍为空，则按城市名补“市”后缀。

### 5.3 区域划分

`AirQualityCrawler.REGION_MAP` 将 31 个省级行政区映射到 7 大区域：

| 区域 | 包含省份 |
|------|----------|
| 华北 | 北京、天津、河北、山西、内蒙古 |
| 华东 | 上海、江苏、浙江、安徽、福建、江西、山东 |
| 华南 | 广东、广西、海南 |
| 华中 | 河南、湖北、湖南 |
| 西南 | 重庆、四川、贵州、云南、西藏 |
| 西北 | 陕西、甘肃、青海、宁夏、新疆 |
| 东北 | 辽宁、吉林、黑龙江 |

未匹配的省份归为“其他”。

### 5.4 爬取流程

核心入口 `AirQualityCrawler.crawlLatest()`，流程如下：

1. **加载候选城市**：从 `city-candidates.csv` 读取，按 `max-city-count`（默认 800）截取。
2. **并发请求**：使用固定大小为 `concurrency`（默认 8）的线程池，对每个城市并发请求接口，单请求超时 15 秒。
3. **解析返回**：接口返回 JSON 数组（每个元素为一个监测站点的数据）。若返回空数组或异常，跳过该城市。
4. **生成记录**：
   - **城市聚合记录**：对该城市所有站点数据取平均值，`city` 字段为城市名（如 `酒泉`）。
   - **站点明细记录**（`station-detail-enabled: true` 时）：每个站点单独入库，`city` 字段为 `城市-站点名`（如 `酒泉-某监测站`）。
5. **数据校验**：所有记录经 `sanitize()` 校验后入库（见 5.5）。
6. **历史扩展**（`history-expansion-enabled: true` 时）：在实时数据基础上按 `history-hours` 回溯生成模拟历史记录，直到达到 `target-record-count`。默认关闭。

线程池在 `fetchCitySnapshots()` 结束后关闭，最长等待 30 秒终止。

### 5.5 数据校验

为保证入库数值准确合理，爬虫在入库前对每条记录执行校验（`AirQualityCrawler.sanitize`）：

1. **AQI 必填且范围校验**：AQI 为空、负数或超过 500 的记录直接丢弃，不入库。
2. **污染物范围校验**：
   - PM2.5、PM10、NO2 取值范围 `[0, 999]`
   - CO 取值范围 `[0, 100]`
   - 超出范围或为负数的字段置为 `NULL`（而非 0），避免把缺失值误判为“极低污染”。
3. **缺失值处理**：接口返回的 `NA`、`-`、`—`、空字符串等无效占位符统一解析为 `NULL`；城市聚合时若所有站点某字段均无有效值，该字段返回 `NULL`（不再返回 0）。
4. **空气质量等级**：统一由 AQI 按 GB 3095 标准重新计算（`levelOf`），保证 `quality_level` 与 `aqi` 一致，不以接口可能缺失或不一致的 `Quality` 字段为准。

AQI 等级划分：

```
0-50        优
51-100      良
101-150     轻度污染
151-200     中度污染
201-300     重度污染
>300        严重污染
```

5. **站点记录过滤**：无站点名（`PositionName` 为空）或无有效 AQI 的站点记录会被丢弃，避免与城市聚合重复或产生无意义数据。

### 5.6 站点明细与展示过滤

开启 `station-detail-enabled: true` 后，每个城市会保存：

```
酒泉                       ← 城市聚合（站点平均值）
酒泉-监测站A               ← 站点明细
酒泉-监测站B               ← 站点明细
```

前端地图与区域对比查询通过 `WHERE city NOT LIKE '%-%'` 过滤掉站点明细（中文城市名不含连字符），只展示城市聚合记录，避免同一城市在页面上重复出现；站点明细保留在数据库中供后续分析使用。

## 六、后端接口

所有接口前缀 `/api`，已在 `WebConfig` 中配置 CORS 允许跨域。

### 6.1 爬虫接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/crawler/run` | 手动触发一次爬取，返回爬虫状态 |
| GET | `/api/crawler/status` | 查询爬虫当前状态 |

**`CrawlerStatusDTO` 返回字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| running | boolean | 是否正在执行 |
| lastSuccess | boolean | 上次是否成功 |
| lastCount | Integer | 上次入库条数 |
| lastMessage | String | 上次执行结果描述 |
| lastRunTime | LocalDateTime | 上次执行时间 |

手动调用 `/api/crawler/run` 不受 `weather.crawler.enabled` 开关影响，随时可用。爬虫任务通过 `AtomicBoolean` 保证同一时刻只有一个任务执行，重复触发会返回“爬虫任务正在执行，请稍后再试”。

### 6.2 分析接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/analysis/china-map` | 获取全国地图散点数据（每城市最新一条） |
| GET | `/api/analysis/region-comparison` | 获取七大区域聚合对比数据 |

**`ChinaMapPointDTO` 字段**：`province`、`region`、`city`、`aqi`、`pm25`、`pm10`、`qualityLevel`、`monitorTime`、`warning`（AQI ≥ 150 时为 true）。

**`RegionComparisonDTO` 字段**：`region`、`avgAqi`、`avgPm25`、`avgPm10`、`cityCount`、`goodCityCount`、`pollutedCityCount`、`goodRate`、`warningCount`。

### 6.3 最新记录查询逻辑

`AirQualityRecordMapper.xml` 中两个查询均通过双层子查询取每个城市最新一条记录：

1. 内层：`GROUP BY city` 取每个城市 `MAX(monitor_time)`
2. 中层：对同一时间点的多条记录取 `MAX(id)` 作为该城市最新行
3. 外层：关联主表取完整字段，并用 `WHERE city NOT LIKE '%-%'` 排除站点明细

### 6.4 演示数据兜底

为避免数据库为空时前端无数据可看，系统提供两层兜底：

1. **后端兜底**：当 `weather.analysis.demo-data-enabled: true` 且数据库查询结果为空时，返回内置演示数据（`AirQualityAnalysisServiceImpl.demoMapPoints` / `demoRegionComparison`，含 15 个示例城市与 7 大区域示例数据）。
2. **前端兜底**：当接口请求失败或返回空数组时，回退到 `src/data/demoData.js` 中的静态数据。

正式使用时可将 `demo-data-enabled` 设为 `false` 关闭后端兜底。

## 七、定时任务

主启动类 `WeatherAnalysisApplication` 标注 `@EnableScheduling` 开启定时任务。

`AirQualityCrawlerTask.scheduledRun()` 按 `weather.crawler.cron` 配置的 cron 表达式定时执行，默认：

```
0 0 */1 * * ?    （每小时整点触发）
```

定时任务受 `weather.crawler.enabled` 开关控制，设为 `false` 则关闭定时爬取。

### 9.2 页面布局

主页面 `AirQualityDashboard.vue` 采用“顶部标题栏 + KPI 指标条 + 三栏内容网格”布局：

- **顶部标题栏**：系统标题、实时数据状态指示（呼吸点动画 + 当前时间）
- **KPI 指标条**（4 卡）：
  - 监测城市数（覆盖省级区域数）
  - 全国平均 AQI（动态语义色条 + 等级描述）
  - 预警城市数（有预警时红色，无预警时绿色）
  - 空气最佳区域
- **三栏内容网格**（`.content-grid`）：
  - 左侧栏：高风险城市 TOP5 排行、空气优良城市 TOP5 排行、PM2.5/PM10 区域对比折线图
  - 中间栏：全国空气质量空间分布地图（粘性定位，滚动时固定在视窗内）
  - 右侧栏：区域平均 AQI 柱状图、区域预警占比环形图、优良率与预警统计组合图

### 9.3 地图组件

`ChinaAqiMap.vue` 基于 ECharts geo 组件实现：

- **地图定位**：使用 `layoutCenter: ['50%','48%']` + `layoutSize: '92%'` 实现确定性居中布局，`scaleLimit: { min: 0.8, max: 4 }` 限制缩放边界，保证地图在页面滚动或窗口大小变化时位置稳定。
- **数据分层**：
  - 省均 AQI 填色（`map` 系列）：按省份聚合城市 AQI 平均值着色
  - 监测城市散点（`scatter` 系列）：青绿色点，大小随 AQI 变化
  - 高危污染城市（`effectScatter` 系列）：红色涟漪点，AQI ≥ 150 的城市
- **预警阈值**：AQI ≥ 150 标记为预警城市，后端 SQL 与前端展示使用同一阈值。
- **视觉映射**：`visualMap` 从绿色（优）到紫色（严重污染）渐变。

### 9.4 图表通用封装

`BaseChart.vue` 封装 ECharts 实例管理：

### 10.3 完整运行流程

## 十一、数据量说明

“全国 696 个城市”是行政区划统计口径，包含大量县级市。本项目使用空气质量实时接口，接口并非对所有县级市都返回数据。

系统对 725 个候选城市以 8 线程并发请求，仅接口真实返回数据的城市才会入库。开启站点明细采集后，单次入库条数约为：

```
城市聚合记录数 + 各城市监测站点记录数总和
```

例如 341 个返回数据的城市，平均每城市 4-6 个监测站点，单次入库约 1500-2000 条。因此数据库中的数量是接口当前可采集到的真实城市与监测站点数量，不使用模拟值或空数据冒充真实采集结果。具体数值随接口实时返回情况波动，以 `/api/crawler/status` 的 `lastCount` 与数据库 `COUNT(*)` 为准。

## 十二、预警规则

前端地图中的红色涟漪点（`effectScatter` 系列）表示空气污染风险较高的城市，判断规则：

```
AQI >= 150
```

后端 SQL 与前端展示使用同一阈值：

- 后端：`CASE WHEN r.aqi >= 150 THEN TRUE ELSE FALSE END AS warning`
- 前端：`item.warning || Number(item.aqi) >= 150`

AQI ≥ 150 对应“中度污染及以上”等级。如需调整预警数量，可同时修改 `AirQualityRecordMapper.xml` 中的 `warning` 判断阈值与前端 `ChinaAqiMap.vue` / `AirQualityDashboard.vue` 中的 `150` 阈值（建议保持一致）。
